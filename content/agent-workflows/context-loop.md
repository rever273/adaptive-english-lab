# Context Loop sentences

Follow the general rules of [common.md](common.md) (the learner does not review content or run commands; never edit SQLite; do not commit). This batch is not an exercise batch: it uses its own commands.

1. `npm run content:loop -- prepare <batch-id>` (run `npm run build` first if the compiled server is missing or older than the source). Read `author-packet.json`: the rules, the targets (word, part of speech, Russian meaning and definition, usage note, words and sentences to avoid) and the draft format.
2. Write `drafts.json`: exactly `sentences_per_target` sentences for every target. Short (5-10 words, 3-14 if natural), natural contemporary Australian/British English, the target ONCE in exactly the given meaning, keeping its usual collocations and patterns. Each sentence of a word has its own situation, people and sentence type; vary topics across the batch. Simple surrounding words. The context must make the meaning understandable after it is revealed but must not define it or make it trivially guessable; never use a listed synonym. Every draft also has `translation_ru`: a natural, accurate Russian translation of the whole sentence with the target in exactly the given meaning (`author` reports a missing or non-Russian one as a PROBLEM). The practice shows it after the answer, so no translation call is spent.
3. `npm run content:loop -- author <batch-id>`. It applies the same code checks as the local model (one occurrence, form, length, synonyms, repeats of the exercise bank, lessons and this word's sentences, repeated openings). Rewrite every PROBLEM and run it again until none remain. Then set `author` in `candidates.json` to `agent:<your identity>@<version>`.
4. `npm run content:loop -- check <batch-id>`, then have the content-reviewer agent (a different identity, never you) read `final-review-packet.json` and write `review.json` from `review-template.json`: `accept`, `flag` (usable idea, real problem; say it) or `reject` for every hash, against the checklist in the packet, including the translation (a wrong or clumsy `translation_ru` is a flag with the corrected translation). A sentence is not wrong only because a rarer but correct wording is used.
5. Repair what the reviewer flags (edit drafts.json, run author and check again) and let the reviewer judge only the changed hashes; the reviewer never approves its own fix. Reject only what cannot be repaired.
6. With the app running (`npm start`), `npm run content:loop -- finalize <batch-id>`. The service checks everything again and writes the batch in one transaction: accepted sentences become `approved`, flagged ones `flagged`, rejected ones are not stored. On refusal fix the reported problem and run it again; an identical retry returns the earlier receipt.
7. Reply briefly: accepted, flagged and rejected counts, then the reviewer's tokens exactly and your own as an estimate.

Work files stay in the ignored `var/agent-batches/context-loop-<batch-id>/`. Never change dictionary entries, attempts, scores or other batches.
